Title

Say the name once: meMO, pronounced me-mo. The title is the story. Start with architecture modeling as code, then explain how the ontology makes safety assurance computable. meMO is a concrete open reference direction, not a product claim.

The opening problem

Open with the public-health question. A medical device is no longer only a physical box. Safety-relevant behavior can live in embedded software, connected services, clinical workflow, released configurations, and AI-enabled functions. The diagram is illustrative, not a claim about one specific product. The point is that the system boundary expanded, so the safety argument must also become system-level.

03 Problem 01 | Complexity moved upward

Software complexity has outgrown component-by-component assurance.

Medical devices are software-defined cyber-physical systems

Safety-relevant behavior now crosses layers, interfaces, and released configurations.

Therapy logic now interacts with hardware, connectivity, workflow, updates, and AI-enabled functions.

Complexity moved upward

Start with the direct argument. Software complexity has moved the safety question above individual components. Do not claim that every AI component is nondeterministic. The concrete point is that AI-enabled functions add model, data, monitoring, and fallback dependencies that must stay visible in the architecture.

04 Why the problem matters now

One safety question. Different pressure across the ecosystem.

The pressures differ. The missing capability is shared.

Regulators + reviewers

Defend the released baseline.

Show the hazard, control, realization, verification, and exact release.

Established manufacturers

Preserve meaning at scale.

Keep assumptions aligned across owners, tools, and years of change.

Startups + small teams

Grow rigor incrementally.

Add structure early without creating a heavyweight process program.

Shared requirementArchitecture-backed evidence that remains explicit, reviewable, and refreshable under change.

Ecosystem pressure

Use the proposal's audit and review expectation carefully. Regulators and reviewers want a defensible released baseline. Established manufacturers struggle with semantic fragmentation across scale and time. Resource-constrained teams struggle to add structure early enough. Do not caricature any group; the shared need is architecture-backed evidence under change.

Document-centric limits

Documents remain part of the regulated lifecycle. meMO is not a document replacement pitch. The issue is using documents and traces as the only analytical substrate for a complex system.

CLI and Architect

Give the requested glimpse. Keep it honest. The CLI entry points and UI modules exist in the repository, but the active branch is hardening native constraints and portability. The UI should remain a thin workbench over source and CLI-equivalent behavior.
